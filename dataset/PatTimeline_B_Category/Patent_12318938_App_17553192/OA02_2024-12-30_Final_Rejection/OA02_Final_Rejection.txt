Claim Rejections - 35 USC § 102
The following is a quotation of the appropriate paragraphs of 35 U.S.C. 102 that form the basis for the rejections under this section made in this Office action:
A person shall be entitled to a patent unless –
(a)(1) the claimed invention was patented, described in a printed publication, or in public use, on sale, or otherwise available to the public before the effective filing date of the claimed invention.
Claim(s) 1-4, 9-14, 19, 20, 25, and 26 are rejected under 35 U.S.C. 102(a)(1) as being anticipated by Weinart, JR. et al. (US 2020/0004798).
With respect to claim 1, Weinart discloses: A computing system, comprising: memory storing computer program instructions for a multi-target robotic process automation (RPA) designer application (Abstract); and
at least one processor configured to execute the computer program instructions, wherein the computer program instructions are configured to cause the at least one processor to ([0102], [0103]):

With respect to claim 2, Weinart discloses: wherein the computer program instructions are further configured to cause the at least one processor to: receive the target platform configuration for the RPA project, receive the multiple target platform versions of the one or more activities of an RPA workflow, or both, after creation by an RPA developer ([0045]).
With respect to claim 3, Weinart discloses: wherein the target platform configuration is or comprises a global scope for the RPA project that generates activities for the plurality of different target platforms automatically within a scope of the RPA workflow ([0011]).
With respect to claim 4, Weinart discloses: wherein when a target platform is not designated, the computer program instructions are further configured to cause the at least one processor to: automatically designate a global scope for the RPA project that generates activities for the plurality of different target platforms automatically within a scope of the RPA workflow without manual selection of the multiple target platforms ([0011]).
With respect to claim 9, Weinart discloses: wherein the RPA workflow comprises a plurality of activities that comprise a tag, a variable, an array, or another descriptor or data structure that specifies one or more target platforms for the respective activity ([0047], variable).
With respect to claim 10, Weinart discloses: wherein the multi-target RPA designer application comprises a project target platform designation option that provides target platform options ([0047], browser automation platform instructions are specific for that job instance).
With respect to claim 11, Weinart discloses: wherein the multi-target RPA designer application comprises an activity target platform designation option that provides target platform options for activities ([0076], Fig. 4A).
With respect to claims 12, 13, and 19, they recite similar limitations as claims 1, 3, and 9, respectively, and are therefore rejected under the same citations and rationale.
With respect to claim 14, Weinart discloses: wherein when a target platform is not designated, the computer program instructions are further configured to cause the at least one processor to automatically designate a global scope for the RPA project that generates activities for the plurality of different target platforms automatically within a scope of the RPA workflow ([0041]).
Response to Arguments
Applicant alleges a web browser is not a “target platform” because the specification gives examples, albeit an open ended one, of target platforms including “legacy targets, .NET Core, cross-platform (e.g., able to run on both Windows and Linux), Apple OS X, native mobile, and the like”. Examiner, respectfully, disagrees that the claim element “target platform” under the broadest reasonable interpretation should have such a narrow interpretation. The claims do not narrow the claim element “target platform” to any of the specified platforms in the specification. It is not incumbent on the Examiner to import limitations from the specification into the claims. In this regard, Weinert discloses creating RPAs that remain vendor and platform agnostic ([0011]). Applicant alleges that a developer can create a workflow in a project that would work for multiple target platforms. However, claim 1 does not disclose a “workflow” or a “developer”. Claim 1 discloses an RPA project configured in accordance with a target platform configuration comprising a plurality of target platforms. The metes and bounds, according to the claim language, of a “project” can include a user utilizing a designer interface to design first and second RPA applications for first and second websites. Weinert utilizes high level wrappers around specific points of robotic process automation to remain vendor and platform agnostic, i.e., specific raw coded scripts for specific platforms are not required. This allows migration to an entirely new underlying technology utilizing the “handler” abstraction layer to design the RPA application. Therefore, Weinert does allow developers/users to build RPA’s for different platforms. With respect to the “configuring multiple versions…version”, the limitation is recited in the alternative and is therefore not provided patentable weight. In the interest of compact prosecution, however, the claim does not disclose what actions constitute said activities. Therefore, under the broadest reasonable interpretation, any endeavor taken with respect to the target web browser is an activity for that web browser. In Weinart, the act of determining a value for the configuration parameter for the website is an activity. This activity is interpreted as having “multiple versions”. The first “version” of the activity determines a first value specific to a first user based on a first context of a first job assistance. The second “version” of the activity determines a second value specific to a second user based on a second context of a second job instance. The activity involves the determination of the value. The versions are merely interpreted as different values that are being determined. Unless the claims are narrowed to include “steps in a RPA workflows, such as clicking a button, opening a file, etc.”, the Examiner will continue to employ the broadest reasonable interpretation. The rejection is, respectfully, maintained.
