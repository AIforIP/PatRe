Claim Rejections - 35 USC § 103
The following is a quotation of 35 U.S.C. 103 which forms the basis for all obviousness rejections set forth in this Office action:
A patent for a claimed invention may not be obtained, notwithstanding that the claimed invention is not identically disclosed as set forth in section 102, if the differences between the claimed invention and the prior art are such that the claimed invention as a whole would have been obvious before the effective filing date of the claimed invention to a person having ordinary skill in the art to which the claimed invention pertains. Patentability shall not be negated by the manner in which the invention was made.
The factual inquiries for establishing a background for determining obviousness under 35 U.S.C. 103 are summarized as follows:
1. Determining the scope and contents of the prior art.
2. Ascertaining the differences between the prior art and the claims at issue.
3. Resolving the level of ordinary skill in the pertinent art.
4. Considering objective evidence present in the application indicating obviousness or nonobviousness.
This application currently names joint inventors. In considering patentability of the claims the examiner presumes that the subject matter of the various claims was commonly owned as of the effective filing date of the claimed invention(s) absent any evidence to the contrary.  Applicant is advised of the obligation under 37 CFR 1.56 to point out the inventor and effective filing dates of each claim that was not commonly owned as of the effective filing date of the later invention in order for the examiner to consider the applicability of 35 U.S.C. 102(b)(2)(C) for any potential 35 U.S.C. 102(a)(2) prior art against the later invention.
Claim(s) 3-5, 7-8 10, 14, 16-17, 18-23 are rejected under 35 U.S.C. 103 as being unpatentable over Rosa  in view of  Ricci  et. al. U.S. Publication No. 20140309879 published Oct 16, 2014.
.
With respect to claims 3-5, 7-8 and 10, Rosa teaches each and every element of claim 1.
Rosa teaches a input device with a dedicated storage device (Para 131) for storing the data structure of gesture identifiers (Para 136-137). Rosa maps the gesture to the application (Para 138). Rosa teaches gesture data as a gesture parameters such as positions, names etc. (Para 137). Rosa teaches reconstructing the gesture and comparing and computing a recommended gesture (Para 138). Rosa teaches the gesture parameter can be the icons, identifier of the application or reference to executable file (Para 140). Rosa compares the input gesture to a tolerance and generates the target instruction for a recommended gesture (Para 130 – 149, Fig. 11-12).  Rosa teaches the gesture data input includes a gesture position and a determining gesture data for a preliminary input and then a current gesture and also generating the parameters for the current and prelim gestures gesture (Para 130 – 149, Fig. 11-12).  The tolerance values of Rosa suggest having different gestures compared in different ranges as degrees of variance (Para 138).
Rosa does not disclose gestures directed to sub-functions or mapping to a preset function or determining when a prior gesture was input the last time.
However, in the analogous art of vehicle user interfaces Ricci teaches allowing a user to input a gesture to control a function on  vehicle (Fig. 11a-11k, and Fig.17).  Ricci teaches determining when a gesture is provided (Para 502) and on which interface (Para 504). The system verifies the input gesture (Para 509, Fig. 20) and identify the gesture by name (parameter). The system can preview the gesture (Para 510-511). Ricci teaches sending the gesture to the application control to control functions of the vehicle (Para 513-515), many of which can be sub-functions (Para 519-520). Ricci teaches communicating parameters to control a number of functions (Para 523-540). Ricci teaches determining if a input was entered by a user prior (Para 548). Ricci teaches the user interface may have a number of function buttons and a second or more interfaces can be provided displaying one or more functions (Para 554-555). Ricci, much like Rosa, compares gestures as input (Para 561) as recognized. Ricci teaches a number of functions and controls can be set by the user to respond to gestures (Para 573).
Accordingly it would have been obvious to the skilled artisan prior to the effective date of the invention having the teachings of Rosa and Ricci in front of them to modify the interface of Rosa, with a reasonable expectation of success with the interface of Ricci so as to map gestures to any number of functions and subfunctions. The motivation to combine Rosa with Ricci comes from the suggestion in Ricci to store a number of gestures and allow the user to create their own gestures that can then be retrieved by the vehicle to react when the gesture is received (Para 488-489).

Rosa teaches a control system for a vehicle (fig. 7) and a device for capturing gestures and a comparison system to determine and compares gestures to inputs (See fig 9-10, claim 1 rejection incorporated herein).
With respect to claim 17, claim 17 as recited reflects all the features of claim 9 computing-processing device, comprising: a memory in which a computer-readable code is stored; and one or more processors, wherein when the computer-readable code is executed by the one or more processors, the computing-processing device executes the method according to claim 9. Therefore claim 17 is rejected in further view of the following along the same rationale as claim 9. Claim(s) 2 and 6 are rejected under 35 U.S.C. 103 as being unpatentable over Rosa et al. in view of Presant et. al. U.S. Publication No. 20190324527 filed Apr. 19, 2019. .
With respect to claims 2 and 6,  as indicated in the above discussion, Rosa teaches each feature of claim 1.
Rosa discloses accessing stored gestures (fig. 9 and 10). Rosa recommends a gesture associated with functions on the interface and when a gesture is input it is compared to a stored gesture that is measured to be within a variance and then a current gesture is sent to the interface.
Rosa does not teach sending the gesture to the interface to display or receiving a wake gesture
However, in the analogous art of gesture and providing input to user interfaces via motion, Presant teaches sending a gesture to the display Fig. 6, para 88). Present also teaches wake up inputs (Para 11, 76). Presant teaches generating inputs from the wake command to control a user interface (Para 76). Presant teaches the interface will guide the user through a set of user interface inputs (Para 77). Presant teaches recommending candidate gestures to a user (Para 79). Presant teaches comparing the gestures to a list of gestures (Para 82) and if incomplete then present a candidate gesture. Presant also compares the gesture to a threshold to determine if the gesture is correct and if not takes remedial action to suggest a recommended gesture (Para 82).
Accordingly it would have been obvious to the skilled artisan prior to the effective date of the invention having the teachings of Rosa and Presant  in front of them to modify the interface of Rosa, with a reasonable expectation of success with the interface inputs of Presant. The motivation to combine Rosa with Presant comes from the suggestion in Presant to determine in different ways the similarity of an input gesture and provide informational cues to a user to suggest how graphically to complete a gesture properly thereby increasing a user satisfaction with the device (Para 83-84).
